# GitHub Secrets Configuration Guide

This guide explains how to configure GitHub secrets for the Real State Search API deployment.

## 🔐 **Required GitHub Secrets**

You need to configure these secrets in your GitHub repository:

### **1. AWS Credentials**
- **Name**: `AWS_ACCESS_KEY_ID`
- **Value**: Your AWS access key ID
- **Description**: AWS access key for deployment

- **Name**: `AWS_SECRET_ACCESS_KEY`
- **Value**: Your AWS secret access key
- **Description**: AWS secret key for deployment

### **2. Database Configuration**
- **Name**: `DATABASE_URL`
- **Value**: `mysql+pymysql://username:password@host:port/database`
- **Description**: Database connection string
- **Example**: `mysql+pymysql://myuser:mypass@my-aurora-cluster.cluster-xyz.us-east-2.rds.amazonaws.com:3306/real_state_db`

### **3. API Keys (Auto-generated)**
- **Name**: `API_KEYS`
- **Value**: `["auto-generated-key-1", "auto-generated-key-2"]`
- **Description**: API keys for Bearer token authentication
- **Note**: These will be auto-generated by API Gateway

### **4. CORS Configuration**
- **Name**: `ALLOWED_HOSTS`
- **Value**: `["api-gateway-url.execute-api.us-east-2.amazonaws.com"]`
- **Description**: Allowed host domains
- **Note**: Will be set to the API Gateway URL after first deployment

- **Name**: `ALLOWED_ORIGINS`
- **Value**: `["https://your-frontend.com", "http://localhost:3000"]`
- **Description**: CORS allowed origins
- **Example**: `["https://myapp.com", "http://localhost:3000"]`

## 🚀 **Setup Process**

### **Step 1: Configure AWS Credentials**
1. Go to your GitHub repository
2. Navigate to **Settings** → **Secrets and variables** → **Actions**
3. Click **New repository secret**
4. Add `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`

### **Step 2: Configure Database URL**
1. Add `DATABASE_URL` secret with your database connection string
2. Format: `mysql+pymysql://user:pass@host:port/database`

### **Step 3: Initial Deployment**
1. Push to `developer` branch
2. GitHub Actions will deploy and generate API Gateway URL
3. Note the generated API Gateway URL from the deployment output

### **Step 4: Update CORS Configuration**
1. After first deployment, update `ALLOWED_HOSTS` with the API Gateway URL
2. Update `ALLOWED_ORIGINS` with your frontend URLs
3. Push again to trigger re-deployment

## 🔧 **Auto-Generated Values**

### **API Keys**
API Gateway will automatically generate API keys. After deployment:

1. Go to AWS Console → API Gateway
2. Navigate to your API → API Keys
3. Copy the generated API key
4. Update the `API_KEYS` secret with the generated key

### **API Gateway URL**
After deployment, you'll get a URL like:
```
https://abc123def.execute-api.us-east-2.amazonaws.com/
```

Use this URL to update `ALLOWED_HOSTS`.

## 📋 **Example Configuration**

### **Initial Setup (Before First Deployment)**
```bash
# GitHub Secrets to configure:
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
DATABASE_URL=mysql+pymysql://myuser:mypass@my-aurora.us-east-2.rds.amazonaws.com:3306/real_state_db
API_KEYS=["temp-key-for-initial-deployment"]
ALLOWED_HOSTS=["localhost"]
ALLOWED_ORIGINS=["http://localhost:3000"]
```

### **After First Deployment**
```bash
# Update these secrets after deployment:
API_KEYS=["abc123def456ghi789"]  # Generated by API Gateway
ALLOWED_HOSTS=["abc123def.execute-api.us-east-2.amazonaws.com"]
ALLOWED_ORIGINS=["https://myapp.com", "http://localhost:3000"]
```

## 🔄 **Deployment Flow**

1. **Initial Push**: Deploys with temporary values
2. **Get API Gateway URL**: From deployment output
3. **Update Secrets**: With generated values
4. **Re-deploy**: With correct configuration

## 🚨 **Security Notes**

- ✅ **Never commit secrets** to the repository
- ✅ **Use GitHub Secrets** for all sensitive data
- ✅ **Rotate API keys** regularly
- ✅ **Use least privilege** AWS IAM policies
- ✅ **Monitor CloudWatch logs** for security events

## 📞 **Support**

If you encounter issues:
1. Check GitHub Actions logs
2. Verify AWS credentials have correct permissions
3. Ensure database is accessible from Lambda
4. Check CloudWatch logs for errors
